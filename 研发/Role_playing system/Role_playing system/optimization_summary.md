# 项目优化点总结

## 已做优化

### 1. 数据优化
- 对输入文本做清洗、归一化，减少脏数据影响。
- 知识库数据统一入库，支持角色化知识源管理。
- 上传文件会先解析、再分块、再入库，保证可检索性。

### 2. 分块优化
- 支持按 chunk size + overlap 切分，兼顾召回和上下文连续性。
- 文件内容、知识库内容分开分块，减少互相干扰。
- 对重复内容做去重，避免检索结果冗余。

### 3. 混合检索
- 已支持 Dense + BM25 + Hybrid + Hybrid Rerank。
- Dense 负责语义召回，BM25 负责关键词召回。
- 混合模式用 RRF 融合多路结果，提升召回稳定性。

### 4. RRF 融合
- 采用 Reciprocal Rank Fusion 融合多路检索结果。
- 降低单一路径失误带来的召回偏差。

### 5. 精排优化
- 在候选集上再做 rerank，提升最终相关性。
- 对候选数量做限制，避免精排成本过高。

### 6. 多轮对话优化
- 引入 Redis 短期记忆保存最近对话。
- 会话历史可回查，支持上下文续写。
- 有请求去重逻辑，避免重复提交重复生成。

### 7. 提示词优化
- 按角色拆分 Prompt 模板。
- 根据是否有知识上下文、文件上下文切换不同提示词。
- 对输出格式做规范化，减少模型“跑格式”。

### 8. 生成结果优化
- 做了输出清洗、重复段落去重、Markdown 规整。
- 支持安全兜底回复，避免模型空答或异常答复。

### 9. 用户问题改写
- 先做问题识别，再决定走知识库、文件分析还是在线模型。
- 对“概览”“全文输出”“轻量问候”“短期记忆”等意图做分流。
- 实际上等于做了轻量的 query routing / rewrite。

### 10. 大模型优化
- 支持 LLM 配置热加载和连接测试。
- 检索不到时自动降级到在线模型。
- 支持流式输出，改善长回答体验。

### 11. 缓存优化
- 向量模型、token、公共知识、用户 chunk 都有缓存。
- Milvus 不可用时自动降级本地检索，保证可用性。
- 单例化检索存储对象，减少重复初始化。

### 12. 代码逻辑优化
- 聊天、文件、检索、配置、服务层分离。
- API 层和业务层拆开，便于维护。
- 有统一异常处理、限流、鉴权、日志。

### 13. 流式输出优化
- Chat 支持 SSE 流式返回。
- 前端可边生成边展示，提升交互感。

## 后续还能怎么优化

### 1. 检索继续优化
- 给知识库和用户文档补索引，减少数据库扫描。
- 引入更稳定的召回评测集，持续调参。
- 对 query rewrite 做显式改写，而不是只靠路由判断。

### 2. 精排继续优化
- 给 reranker 做常驻进程或服务化，减少子进程开销。
- 对不同角色使用不同候选数和阈值。
- 增加 rerank 失败时的兜底策略。

### 3. 数据继续优化
- 给知识源加版本号、更新时间、来源可信度。
- 文件解析结果做结构化存储，减少重复解析。
- 对低质量知识卡片做自动过滤。

### 4. 多轮对话继续优化
- 把短期记忆和长期记忆分层。
- 增加对用户偏好、角色设定、任务状态的持久记忆。
- 历史对话做摘要压缩，降低 Prompt 长度。

### 5. 生成继续优化
- 增加“先给结论，再给依据”的模板约束。
- 对法律、医疗、心理等角色加入更强的安全边界。
- 增加引用来源展示，提升可解释性。

### 6. 性能继续优化
- 把耗时的文件解析、OCR、入库改成后台任务。
- 对热数据做 TTL 缓存和异步预热。
- 压测下拆分 chat 主链路和文件链路，分别优化。

### 7. 工程继续优化
- 把超长 `rag_chain.py` 再拆成检索、路由、提示词、输出四层。
- 给关键链路补单测和回归测试。
- 增加可观测性：检索命中率、LLM 延迟、rerank 耗时、降级次数。

---

## 一句话总结

这个项目的核心优化方向已经很清晰：**先用混合检索把信息找准，再用精排把结果排稳，最后用 Prompt + 记忆 + 流式输出把回答体验做顺。**
