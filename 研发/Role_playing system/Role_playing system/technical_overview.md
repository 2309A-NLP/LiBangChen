# 多角色 RAG 系统技术整理

## 1. 项目大流程

1. 用户通过 `FastAPI` 接口发起登录、建会话、聊天、上传文件等请求。
2. `ChatBot` 负责业务编排，管理用户、会话、消息、知识文档和文件。
3. `RAGChain` 负责检索增强生成：
   - 先从知识库、PDF、用户上传文件中检索上下文。
   - 再把“角色提示词 + 历史对话 + 检索结果”组装成 Prompt。
   - 最后调用大模型生成回复。
4. `Redis` 用于短期对话记忆，保存最近消息和压缩上下文。
5. `Milvus` 用于向量检索；不可用时会降级到本地数据库检索。
6. `Reranker` 对候选结果再次排序，提高最终检索精度。
7. 系统支持评测、知识同步、文件解析和性能测试。

## 2. 核心技术栈

- `FastAPI`：后端接口框架。
- `SQLAlchemy`：数据库 ORM，用于用户、会话、消息、知识文档管理。
- `Redis`：短期记忆和会话上下文缓存。
- `Milvus`：向量数据库，做语义检索。
- `SentenceTransformers / BGE-M3`：文本向量化。
- `BGE-Reranker`：候选结果重排序。
- `BM25`：词法检索方法。
- `OpenAI API 兼容客户端`：调用大模型生成回答。
- `PyMuPDF / pdfplumber / OCR`：PDF 与图像文字提取。
- `RAGAS / JMeter`：效果评测与压测。

## 3. 关键技术定义

### 3.1 RAG

RAG（Retrieval-Augmented Generation，检索增强生成）是“先检索，再生成”的问答框架。
它的目标不是让模型凭空回答，而是先从知识库找证据，再结合证据生成回复。

### 3.2 向量检索

把文本编码成向量，通过向量相似度找最相关内容。
本项目中主要用于语义召回，适合“意思相近但字面不同”的问题。

### 3.3 词法检索

基于词项重合、词频和逆文档频率进行匹配。
适合关键词明确、专有名词较多的场景。

### 3.4 重排序

先粗召回一批候选，再用更强的模型重新打分排序。
作用是提升最终返回结果的相关性。

### 3.5 短期记忆

用 `Redis` 保存最近对话，保证多轮问答能记住上下文。

## 4. 核心公式

### 4.1 余弦相似度

向量语义相似度常用公式：

$$
\cos(\theta) = \frac{A \cdot B}{\|A\|\|B\|}
$$

如果向量已归一化，点积就可以近似表示相似度。

### 4.2 点积

本项目本地 embedding 检索中使用点积：

$$
score = \sum_{i=1}^{n} q_i d_i
$$

其中 $q$ 是查询向量，$d$ 是文档向量。

### 4.3 BM25

BM25 是经典词法检索打分函数：

$$
score(D,Q)=\sum_{i=1}^{n} IDF(q_i)\cdot \frac{tf(q_i,D)(k_1+1)}{tf(q_i,D)+k_1\left(1-b+b\frac{|D|}{avgdl}\right)}
$$

其中：

- $tf$：词项在文档中的出现次数
- $IDF$：逆文档频率
- $|D|$：文档长度
- $avgdl$：平均文档长度
- $k_1, b$：BM25 参数

### 4.4 RRF 融合

RRF（Reciprocal Rank Fusion）用于融合多路召回结果：

$$
RRF(d)=\sum_{r \in R}\frac{1}{k + rank_r(d)}
$$

其中：

- $R$：检索结果来源集合
- $rank_r(d)$：文档在某一路召回中的排名
- $k$：平滑参数

### 4.5 重排序

重排序模型会对“查询-候选文档”成对打分：

$$
score = f(query, document)
$$

分数越高，表示该候选越相关。

## 5. 模块职责

- `app.py`：程序入口。
- `api/app_factory.py`：FastAPI 应用工厂，注册中间件和路由。
- `api/routes/conversations.py`：聊天与会话接口。
- `chat_bot.py`：核心业务逻辑层。
- `rag_chain.py`：RAG 编排核心。
- `vector_store.py`：向量检索、BM25、RRF、重排序。
- `redis_memory.py`：短期记忆。
- `knowledge_sync_service.py`：知识库同步。
- `prompts.py`：角色 Prompt 模板。
- `config.py`：统一配置中心。

## 6. 这套系统的特点

- 支持多角色对话。
- 支持知识库检索增强回答。
- 支持 PDF、文本、用户上传文件。
- 支持混合检索与重排序。
- 支持 Redis/Milvus 降级。
- 支持接口、评测、压测和知识同步。
