# RAG Q&A 系统优化方案

## 1. 背景与现状

当前系统已经具备可运行的 PDF RAG 问答主链路，核心能力包括：

- PDF 上传、解析、缓存与知识库管理。
- 基于全文检索、向量检索、RRF/加权/投票融合的混合召回。
- Cross-encoder、TF-IDF、反馈、LLM 等多种重排策略。
- Query Understanding 的本地规则、在线模型和本地优先降级策略。
- 同步问答、SSE 流式问答、引用来源返回、会话上下文改写。
- LightRAG sidecar 集成与 Hybrid/LightRAG 对比脚本。
- RAGAS 采样与评估脚本。
- 针对表格、图表、财务指标、法定代表人、获奖工程等场景的局部抽取规则。

现阶段的主要优化方向不是补齐基础功能，而是提升答案准确率、召回稳定性、复杂 PDF 解析质量、评估闭环和工程可维护性。

## 2. 优化目标

### 2.1 质量目标

- 检索命中率：核心业务问题 Top-8 召回命中率达到 90% 以上。
- 引用准确率：答案引用片段能够支撑结论，目标达到 85% 以上。
- 幻觉率：无依据生成、答非所问、跨文档串用证据显著下降。
- 表格/图表问答：金额、占比、增长率、组织架构等结构化问题稳定返回可核验答案。
- 中英文问答：英文问题不再明显弱于中文问题，至少保证实体、指标、年份可稳定召回。

### 2.2 性能目标

- 常规文本问题 P95 响应时间控制在 8 秒内。
- 非视觉解析场景避免不必要的多模态调用。
- 重排模型按需加载、可观测、可降级。
- 大 PDF 上传后解析、索引、预热过程可追踪、可恢复。

### 2.3 工程目标

- 建立固定评测集和回归评测流程。
- 将检索、重排、生成、解析错误拆开定位。
- 降低规则散落和乱码注释带来的维护成本。
- 所有优化可通过配置或实验脚本验证，不依赖手工主观判断。

## 3. 问题诊断

### 3.1 文档解析

当前解析层已经支持 `pypdf`、Doubao 视觉解析和 `auto` 模式，但仍存在以下风险：

- 普通文本页和图表页的判定规则偏粗，可能漏掉图表中的关键数值。
- 表格 chunk 仅按长度聚合，缺少表头继承和跨页表格合并。
- 缓存签名已包含解析参数和模型版本，但缺少解析质量指标记录。
- README 和部分源码注释存在编码异常，影响交接与维护。

### 3.2 检索召回

当前默认混合检索已经具备较好基础，但可进一步优化：

- 全文检索、向量检索、LightRAG 的适用场景边界需要更清晰。
- RRF 参数、候选集大小、全文/向量权重缺少系统化调参记录。
- 英文问题依赖中文语料时，关键词扩展和实体归一化不足。
- 结构化问题依赖局部规则，覆盖范围有限。

### 3.3 重排与生成

当前支持多重排器串联，但存在成本和稳定性问题：

- Cross-encoder 首次加载慢，CPU 推理对延迟影响明显。
- LLM reranker 成本高且稳定性依赖外部服务。
- 局部抽取规则能提升精确答案，但规则散落在生成服务中，长期会变重。
- 生成 fallback 已存在，但缺少“拒答/证据不足”的统一策略。

### 3.4 评估闭环

项目已有 RAGAS 脚本和 LightRAG 对比脚本，但需要产品化：

- 缺少固定问题集、标准答案、证据页码、问题类型标签。
- 缺少每次优化前后的指标对比表。
- 缺少失败样本归因分类，例如解析失败、召回失败、重排失败、生成失败。
- 缺少自动化阈值，不能阻止质量回退。

## 4. 总体优化策略

采用“评估先行、召回优先、生成收口、工程固化”的顺序推进。

1. 先建立标准评测集和失败归因，让优化有可比数据。
2. 优先优化解析和召回，因为生成模型无法弥补缺失证据。
3. 对表格、图表、财务指标等高价值场景做结构化增强。
4. 对重排、LLM 调用和 LightRAG 做按场景路由，而不是全部默认开启。
5. 最后补齐可观测性、配置治理、文档和回归测试。

## 5. 分阶段实施方案

### 阶段一：评估基线与问题集建设

优先级：P0

目标：明确当前系统真实质量，避免凭感觉优化。

实施项：

- 建立 `eval/questions.json`，每条样本包含：
  - `question`
  - `source`
  - `ground_truth`
  - `expected_pages`
  - `question_type`
  - `difficulty`
- 问题类型至少覆盖：
  - 基础事实类：公司名称、法定代表人、注册资本、成立时间。
  - 财务指标类：收入、毛利率、金额、占比、报告期变化。
  - 表格类：前五大客户、供应商、销售金额、采购金额。
  - 图表类：组织架构、增长率、趋势、占比。
  - 关系类：股东、控制人、子公司、关联方。
  - 归纳类：业务模式、风险因素、竞争优势。
  - 多轮追问类：代词、省略、承接上一问。
  - 英文问题类：英文问中文招股书内容。
- 扩展 `scripts/run_ragas_eval.py` 输出：
  - 平均延迟。
  - 引用页命中率。
  - 空召回率。
  - 失败样本列表。
- 将 `scripts/compare_rag_lightrag.py` 输出升级为更详细的 Markdown 报告：
  - Hybrid 与 LightRAG 的答案对比。
  - 引用数量、页码、chunk id。
  - debug 中的 retriever、reranker、timing。

验收标准：

- 至少 80 条核心评测问题。
- 每次运行能生成 `samples.json`、`scores.json`、`scores.csv`、`failure_report.md`。
- 能明确区分召回失败、重排失败、生成失败、解析失败。

### 阶段二：PDF 解析与 chunk 质量优化

优先级：P0

目标：提升源材料质量，减少由于解析错误导致的召回失败。

实施项：

- 为每个 PDF 记录解析质量指标：
  - 页数。
  - chunk 数。
  - 空文本页数。
  - 视觉解析页数。
  - 表格页数。
  - 平均 chunk 长度。
  - 警告列表。
- 优化 `auto` 视觉升级策略：
  - 不仅根据文本长度和图表关键词判断，还根据数字密度、表格符号密度、图片页低文本比判断。
  - 对含“图”“表”“增长率”“占比”“组织结构”等关键词的页提高视觉解析优先级。
- 增强表格 chunk：
  - 表头继承到每个表格 chunk。
  - 对跨页表格保留上一页表头。
  - 对金额、百分比、年份列添加轻量结构化摘要。
- 为 chunk 增加 metadata：
  - `chunk_type`: `text`、`table`、`chart`、`vision`
  - `page_number`
  - `section_title`
  - `has_numeric_data`
  - `parser_provider`
- 修复或重写乱码注释和 README 中影响理解的关键说明。

验收标准：

- 表格类问题 Top-8 召回命中率提升。
- 图表类问题不再大量空召回。
- 知识库页面能展示 chunk 类型和解析警告。

### 阶段三：检索召回优化

优先级：P0

目标：提升正确证据进入候选集的概率。

实施项：

- 对 `hybrid` 检索做参数实验：
  - `HYBRID_CANDIDATE_MULTIPLIER`: 3、5、8、10。
  - `RRF_K`: 30、60、100。
  - `HYBRID_FULLTEXT_WEIGHT` 与 `HYBRID_VECTOR_WEIGHT` 的组合。
  - `DEFAULT_TOP_K`: 6、8、10、12。
- 增强 Query Understanding 的检索提示：
  - 年份、金额、百分比、公司实体、章节名独立抽取。
  - 英文问题转写出中文关键词和中文同义词。
  - 对财务/表格/图表问题添加 `chunk_type` 偏好。
- 召回结果加入多样性约束：
  - 避免 Top-K 被同一页或同一大段重复占满。
  - 对多文档查询保留来源多样性。
- 增加 LightRAG 场景路由：
  - 关系类、股权类、控制关系类优先尝试 LightRAG。
  - 明细表格、金额数值类优先 Hybrid。
  - 归纳总结类可 Hybrid + LightRAG 双路召回后融合。
- 增加检索 debug 的可读字段：
  - 每个候选来自全文、向量、LightRAG 的排名。
  - 命中的关键词。
  - 原始分数和融合分数。

验收标准：

- Top-8 引用页命中率达到目标值。
- 空召回率明显下降。
- Hybrid、LightRAG、融合策略的适用边界形成文档。

### 阶段四：重排与答案生成优化

优先级：P1

目标：让正确证据排在前面，并让生成严格基于证据。

实施项：

- 重排策略按场景启用：
  - 常规问题：`cross_encoder`。
  - 大候选集或 CPU 压力高时：`tfidf + feedback`。
  - 高价值复杂问题：`cross_encoder + llm`。
- 增加重排前后对比 debug：
  - rerank 前排名。
  - rerank 后排名。
  - 分数变化。
- 把局部抽取规则从 `RetrievalGenerationService` 中逐步拆成独立 extractors：
  - `FinancialMetricExtractor`
  - `LegalRepresentativeExtractor`
  - `AwardProjectExtractor`
  - `ChartStructureExtractor`
- 建立统一证据不足策略：
  - 无引用时拒答。
  - 引用分数低于阈值时提示证据不足。
  - 生成答案必须带引用页，否则返回可核验片段摘要。
- 优化 LLM prompt：
  - 明确“只能依据给定片段回答”。
  - 金额、年份、百分比必须逐项列出来源。
  - 多文档问题必须说明来源文档。
  - 中英文问题按用户语言回答，但实体名保留原文。

验收标准：

- 幻觉类失败样本减少。
- 复杂问题答案引用能直接支撑结论。
- 重排开启/关闭的收益可通过评测报告量化。

### 阶段五：性能与稳定性优化

优先级：P1

目标：提升服务可用性，减少慢请求和外部模型故障影响。

实施项：

- 启动阶段异步预热：
  - 文档缓存加载。
  - 向量索引加载。
  - cross-encoder 可选预加载。
  - LightRAG 健康检查。
- 增加分层超时：
  - Query Understanding。
  - 检索。
  - 重排。
  - 生成。
  - 视觉解析。
- 增加外部模型熔断：
  - 连续失败后短时间内走本地 fallback。
  - 对 401、403、欠费、超时进行明确错误归类。
- 优化重排性能：
  - CPU 环境下降低候选数。
  - 支持 batch size 配置。
  - 支持按请求禁用 reranker。
- 优化缓存：
  - 问题改写缓存。
  - embedding 缓存。
  - LightRAG 查询结果短期缓存。
  - 评估脚本样本缓存。

验收标准：

- 常规问题 P95 延迟达到目标。
- 在线 LLM 或视觉模型异常时，系统可降级返回可解释结果。
- 预热状态接口能准确反映当前可用能力。

### 阶段六：反馈学习与持续优化

优先级：P2

目标：让用户反馈进入检索和重排改进闭环。

实施项：

- 扩展反馈数据结构：
  - `answer_id`
  - `question`
  - `rating`
  - `comment`
  - `selected_citation_ids`
  - `missing_answer`
  - `wrong_citation`
- 在知识库或管理页面增加低分反馈查看。
- 将高频低分问题自动加入候选评测集。
- 优化 `FeedbackAdaptiveReranker`：
  - 正反馈提升命中词。
  - 负反馈降低误召回词。
  - 按 source 和 question_type 分组建模。

验收标准：

- 低分问题能追踪到原始 query、引用、debug 和用户反馈。
- 每轮优化能沉淀新增回归用例。

## 6. 推荐优先级清单

### P0：必须优先完成

- 建立固定评测集和失败归因报告。
- 增强 PDF 解析质量指标。
- 优化表格和图表 chunk。
- 做 Hybrid 参数实验并固化默认配置。
- 增强英文问题的中文关键词扩展。
- 增加证据不足拒答策略。

### P1：质量与体验提升

- 按问题类型做检索路由。
- LightRAG 与 Hybrid 双路融合。
- 拆分局部抽取 extractors。
- 完善重排前后 debug。
- 增加性能指标和外部模型熔断。

### P2：长期演进

- 反馈驱动重排画像。
- 管理后台评测报告展示。
- 多租户或多知识库选择。
- 更细粒度权限、安全审计和操作日志。

## 7. 配置建议

推荐先使用以下基线配置做评测：

```env
PDF_PARSER_PROVIDER=auto
RETRIEVER_TYPE=hybrid
HYBRID_TEXT_RETRIEVER=fulltext
HYBRID_FUSION_STRATEGY=rrf
HYBRID_CANDIDATE_MULTIPLIER=5
RRF_K=60
DEFAULT_TOP_K=8
RERANKER_ENABLED=true
RERANKER_TYPES=cross_encoder
RERANKER_TOP_N=8
QUERY_UNDERSTANDING_MODE=online
QUERY_UNDERSTANDING_LOCAL_FIRST_ENABLED=true
QUERY_UNDERSTANDING_FALLBACK_ENABLED=true
```

调参时建议固定评测集，只改变一个变量，避免无法判断收益来源。

## 8. 验收指标

| 指标 | 当前基线 | 目标 | 说明 |
|---|---:|---:|---|
| Top-8 引用页命中率 | 待测 | >= 90% | 标准答案页码进入引用结果 |
| Context precision | 待测 | >= 0.80 | RAGAS 指标 |
| Context recall | 待测 | >= 0.80 | RAGAS 指标 |
| Faithfulness | 待测 | >= 0.85 | RAGAS 指标 |
| 空召回率 | 待测 | <= 5% | 没有 citation 或 citation 无内容 |
| 表格问题准确率 | 待测 | >= 85% | 金额、占比、年份正确 |
| 图表问题准确率 | 待测 | >= 75% | 视觉解析和 chart fallback 生效 |
| 常规问题 P95 延迟 | 待测 | <= 8s | 不含首次模型加载 |

## 9. 风险与应对

| 风险 | 表现 | 应对 |
|---|---|---|
| 外部 LLM 不稳定 | 超时、403、欠费 | 本地规则 fallback、熔断、错误分类 |
| PDF 解析不稳定 | 扫描件、图表丢数、跨页表 | auto 视觉升级、表头继承、解析质量报告 |
| 重排延迟高 | CPU 推理慢 | 降候选数、按场景启用、可配置 batch size |
| 规则越来越重 | 生成服务膨胀 | 拆分 extractor，建立单测 |
| 优化不可复现 | 手工判断答案好坏 | 固定评测集、保存 samples 和 scores |
| 英文问题效果差 | 中文资料召回弱 | 英文问题中文关键词扩展和实体归一化 |

## 10. 建议落地顺序

第一周：

- 建立 80 条评测集。
- 输出基线评测报告。
- 增加失败归因字段。
- 修复关键文档乱码。

第二周：

- 增强表格/图表解析和 chunk metadata。
- 做 Hybrid 参数实验。
- 固化最佳默认配置。

第三周：

- 引入按问题类型的检索路由。
- 完善 LightRAG 对比与融合。
- 优化英文问题关键词扩展。

第四周：

- 拆分 extractors。
- 增加证据不足策略。
- 增加熔断、性能指标和回归测试。

## 11. 交付物

- `eval/questions.json`：标准评测问题集。
- `reports/rag_eval_baseline.md`：当前基线报告。
- `reports/rag_eval_after_optimization.md`：优化后报告。
- `reports/failure_report.md`：失败归因报告。
- `docs/RETRIEVAL_STRATEGY.md`：检索策略与参数说明。

## 12. 结论

当前系统已经具备较完整的 RAG 工程基础，后续优化重点应从“继续堆功能”转为“用评测闭环驱动质量提升”。建议先完成评测集、失败归因、解析质量指标和 Hybrid 参数实验，再推进 LightRAG 路由、结构化抽取、证据不足策略和性能治理。这样可以确保每一项优化都有明确收益，并能长期防止质量回退。
