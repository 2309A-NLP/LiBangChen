# 项目亮点

## 一句话介绍

这是一个基于 RAG 的 PDF 智能问答系统，支持多轮对话、Query Understanding、混合检索、流式回答和答案溯源，兼顾问答效果、交互体验与工程可扩展性。

## 核心优点

### 1. 支持多轮对话，交互更自然

系统支持 `session_id` 持久化，前端会自动保存会话标识，页面刷新后仍可恢复历史消息。  
这意味着用户可以围绕同一份文档连续追问，而不是每次都从零开始，整体体验更接近真实的智能助手。

### 2. 检索前先做 Query Understanding

项目在检索前增加了 Query Understanding 模块，可完成：

- 意图识别
- 歧义检测
- 问题拆解
- 检索提示生成

这种设计能让系统先“理解问题”再“检索内容”，对复杂问题、模糊问题和连续追问更友好，也更有利于提升召回质量。

### 3. 检索策略完整，不依赖单一路径

系统支持多种检索方式：

- 关键词检索（BM25）
- 向量检索（Milvus）
- 混合检索（RRF 融合）
- 可选重排（Reranker）

这说明项目不是简单把文档丢给大模型，而是在检索链路上做了更完整的工程设计，有助于提升答案相关性和稳定性。

### 4. 回答结果支持引用溯源

每次回答都可以附带引用信息，包括来源文档、页码和片段摘要。  
这对于 PDF 问答场景尤其重要，因为它不仅给出答案，还能告诉用户“答案来自哪里”，提高系统的可信度和可解释性。

### 5. 支持流式问答，响应体验更好

系统提供流式问答接口，前端通过 SSE 接收结果。  
相比一次性等待完整答案返回，流式输出能降低用户等待焦虑，增强系统的实时交互感。

### 6. 文档管理能力较完整

除了上传 PDF 和提问，系统还支持：

- 文档重载
- 指定检索文档
- 查看知识库文档列表
- 查看文档分块详情
- 删除文档后自动重建索引

这让项目不只是一个“问答 Demo”，而是已经具备一个轻量知识库系统的基本形态。

### 7. 有后台预热机制，首问更稳

系统在启动后或文档更新后，会在后台执行检索预热，并提供 warmup 状态查询接口。  
这体现出项目考虑了真实使用中的性能体验，而不只是功能是否“能跑通”。

### 8. 有反馈闭环，方便后续迭代

系统支持对回答结果进行评分和文本反馈记录。  
这为后续优化检索效果、调整提示词、分析回答质量提供了数据基础，具备持续迭代空间。

### 9. 模块化设计，扩展性较强

项目中检索器、LLM、会话存储、重排器等模块都采用了可切换设计，可通过配置进行切换。  
这让系统在开发、测试和后续部署时更灵活，也更适合继续扩展新能力。

### 10. 有成本意识，能兼顾效果与开销

项目采用了 `local-first` 的 Query Understanding 策略，并对部分场景提供本地精确抽取能力。  
这意味着系统并不是所有问题都直接调用在线大模型，而是优先用本地规则和结构化抽取解决简单或高确定性问题，从而达到：

- 减少不必要的 LLM 调用
- 降低推理成本
- 缩短响应延迟

## README 版文案

本项目是一个基于 RAG 的 PDF 智能问答系统，除了支持文档上传、解析、检索和回答生成外，还具备较完整的多轮对话与知识库管理能力。系统支持 `session_id` 持久化，可在刷新页面后恢复历史会话，实现连续追问和上下文关联问答，提升了实际使用体验。

在能力设计上，项目不仅实现了基础问答，还加入了 Query Understanding 模块，可在检索前完成意图识别、歧义检测、问题拆解和检索提示生成，从而提升复杂问题的理解能力与检索准确率。同时，系统支持关键词检索、向量检索和混合检索，并可选接入 reranker，回答结果还带有引用溯源，便于定位原文依据，增强可解释性和可信度。

在工程实现上，项目支持流式问答、后台预热、反馈闭环和模块化配置，检索器、LLM、会话存储等组件均可灵活切换，兼顾了效果、体验与可扩展性。尤其是 `local-first` 的 Query Understanding 策略和部分本地精确抽取能力，可以减少不必要的大模型调用，在保证效果的同时帮助系统省成本、降延迟。
